# 路线图：从“能抓”到“每天真的会看”

## 定位（重要）

不要做成“又一个信息聚合站”。目标只有一个：

> **每天早上 5 分钟，读完 AI 领域真正值得知道的事。**

判断标准：如果你连续 3 天没打开，说明源选错了，不是站做得不够全。

## 四周计划

### 第 1 周（已完成）
- 多源采集：一手 4 个（smol.ai / The Batch / HF Papers / arXiv）+ 榜单 + 广谱 + 搜索，共 21 个源
- 去重（URL + 标题近重复）、分层打分、AI 相关性加权
- 静态站（`site/index.html`）+ 日报（`data/digest-*.md`）
- 源健康检查（`data/health.json`）：连续失败 / 超 3 天未更新自动标红
- 每日自动：开机自启 + 每 6 小时一次

### 第 2 周：让它“来找你”
- 固定时间任务（管理员权限跑 `install_task_admin.bat`，08:00 / 20:00）
- 推送：邮件（SMTP）或 企业微信/飞书 webhook —— 打开率远高于打开网页
- 历史归档：`site/archive/2026-11-07.html`，可回看
- 源失败告警：连续失败 3 次推一条消息

### 第 3 周：补最缺的两块
- X / Twitter（Apify，免费 $5/月 ≈ 2 万推文）
- LLM 导读（`OPENAI_API_KEY` 一设就生效，400 字趋势综述，失败自动退回结构化版）

### 第 4 周：把“榜单”变成资产
- LMArena / Artificial Analysis / alphaXiv 做每周快照
- 只报**变化**：排名升降、价格变动、新条目 —— 比刷新榜单有用得多

## 维护纪律

1. **源到 30 个就停**。再加只会稀释信噪比。
2. 每周看一次健康面板：连续标红的源直接删掉，不要“以后修”。
3. 日报里同源最多 2 条、总数封顶 20 条 —— 少而准。

## 为什么现在不急着接 X 和 LLM

采集管线还没跑满一周，你不知道哪些源真的会被你读。
这时候加通道只会放大噪声、掩盖“到底该看什么”这个问题。
先用一周数据回答：**哪 3 个源贡献了 80% 的必看条目？** 答案出来后再决定加什么。
