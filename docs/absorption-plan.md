# AIHOT 能力吸收路线（全量对齐 + 反向超越）

> 目标：AIHOT 有的我都要有；AIHOT 没有的、对我有用的，我更要有。
> 约束：每一步都必须保证 `python run.py` 能跑完、产物不倒退。
> 对照对象：`docs/aihot-analysis.md`（它的实现细节与证据）。

---

## 总原则

1. **吸收的是机制，不是体量。** AIHOT 的 21k 行里有一大半是为"一套代码服务多个行业站 + 线上高并发"付的账，那部分不抄。抄的是它解决问题的**顺序**和**判据**。
2. **能配置的不写进代码。** 口径在 `config/scoring.yaml`，判断在 `config/prompts/`，代码只做机制。
3. **任何增强都必须可降级。** LLM 挂了、预算尽了、结果不明 —— 退回老路径，绝不阻断出刊。
4. **每一步都要能验证。** 没有验收标准的改造不做（见每期的"验收"）。

### P2（本轮已完成）事件聚簇 + 热度

- ✅ `collector/events.py`：IDF 加权 token 召回 → 只把够像的对送模型 → 四类关系判定 → 低置信度独立复核
- ✅ `config/events.yaml`：召回窗口/粗排门槛/预算闸/复核线/热度参数
- ✅ `config/prompts/{group-pair,group-review}.md`
- ✅ `event_pairs` 判定缓存：同一对永不重复付费（有测试守着）
- ✅ 热度 `Σ 0.5^(Δt/24h)` + 独立参与方 + `participant_groups`
- ✅ 代表稿选择 + 日报只出代表稿（`digest._pick`）+ `N 篇/N 家` 标注
- ✅ 单篇不建事件壳（215 条里 199 条），落库改为批量事务

**实测（真实 215 条，本地 glm-5.3-flash）**：
```
候选判定 24 对（一轮约 47s，4 并发）
→ 9 个多篇事件，合并 17 条
→ Claude Fable 5.2 一个事件合并 7 篇（HN / X×3 / Telegram / oneusefulthing）
→ 模型输出 confidence 0.85，回执 attempts=1，二次调用命中回执不花钱
```

**验收**：43 个测试全绿，其中 LG 那两条是活的回归用例。

### P3（本轮已完成）结构化 + 指纹 + 防幻觉

- ✅ `config/taxonomy.yaml`：8 类 + 标签词表 + 实体别名 + grounding 豁免词
- ✅ `config/prompts/structure.md`：分类/标签/主体/scope/事实，越界值丢弃
- ✅ `collector/structure.py`：批量抽取（默认只抽分最高的 120 条）+ 落 `structures` 表
- ✅ `collector/grounding.py`：专名（只查大写）+ 数字（% / 小数 / 4 位以上）逐个比对语料
- ✅ 内容指纹 `sha256(title|summary)` + `revision` 字段：内容被更新会被标出来
- ✅ 日报导读改走回执层（原来裸调 `requests`，绕过缓存与预算），**生成后过 grounding 才用**

**实测（真实数据 + 本地模型）**：
```
结构化 10 条 / 12 秒：分类全部合理（model_release / opinion_analysis / industry_event / tool_or_prompt）
  只有标题的那条 → scope=unknown（正确地不猜）
  有摘要的 → fact 抽出 Anthropic / 发布 / Claude Fable 5.2 / 2026-11-09
导读 1098 字 → grounding 复核 ok，548 条评论 / 65 分 / 49.9 美元等数字全部可溯源
反向用例：模型写出 "Latent Space"（源站名）会被判编造 → 已把源名纳入豁免
```

**验收**：63 个测试全绿；`grounding` 的正反用例都在（编造公司 / 编造百分比 / 小写英文不误判 / 年份豁免）。

### P4（本轮已完成）成刊规则化 + 告警

- ✅ `collector/edition.py`：重要性 = 分数 + 参与方加成 + 一手加成 − 跟进扣分 − 空标题扣分

- ✅ **空标题不当头条**（`headline_eligible`）：`太疯狂了` 这类降级到"其他值得知道"，但不删
- ✅ 同分按 URL 定序：同一批内容换个抓取顺序，排出的还是同一期
- ✅ `collector/alerts.py`：源连续失败 / 长期静默 / 缺期 / 缺期断层 / 预算耗尽 / 失败率
- ✅ 出刊记录 `editions` 表：能判"今天该出没出"；告警同一天同一条只发一次
- ✅ `pushmail.send_text`：告警走同一套 SMTP（也顺便给 P7 多通道留了入口）
- ✅ 顺手修掉两个渲染 bug：多行摘要打断编号列表；`## 国外 · 今日必看` 与新编排重复

**实测（真实 215 条，无模型参与）**：
```
编排: 头条 1 · 看点 3 · 正文 8 · 快讯 0
头条: Claude Fable 5.2 与 Mythos 5.2 发布
「太疯狂了」被降级到"其他值得知道"（不再占看点位置）
告警: 4 条（源静默 / 源连续失败 / 缺期 / 缺期断层），第二轮新写入 0 条
```

**验收**：89 个测试全绿。

### P5（本轮已完成）正文提取 + 日期补全

- ✅ `collector/extract.py`：抓原文页，按语义容器与"段落密度"选正文；日期按 meta → `<time>` → JSON-LD 三级回退
- ✅ 正文门槛 `min_body_chars`：太短的多半是拦截页/登录页，宁可没有正文
- ✅ 知乎：`search_v3` 的 `created_time` 之前被丢掉，现在补上（**这是最大的单一修复**）
- ✅ 微博：搜索卡片的时间（`今天03:11` / `11月08日 15:47`）按位置对齐提取，对不上就留空
- ✅ 先打分再抓正文（用老分挑），抓完用新日期重算一次分数（纯 CPU，很便宜）

**实测**：
```
正文：8 条样本 → 5 条拿到真正文（6000 / 4240 / 696 字），3 条是 X 的 JS 页面被正确跳过
知乎：5/5 拿到日期 —— 而它们其实是 2024/2025 年的常青内容，
      之前被当成"48 小时内的新料"，现在会自然沉底
微博：4/6 拿到日期（解析不出的保持空，不填错）
```

**为什么这条比看上去重要**：215 条里 43 条无日期（知乎 15 / 微博 15 / 头条 7 / 36 氪 6）。
无日期时 `_age_hours` 一律按 48 小时算，于是"半年后的旧文"和"两小时前的新闻"拿到同样的时效分。
补上真实日期后，一大批常青内容自动掉出日报。

### P6（本轮已完成）多出口

**验收**：120 个测试全绿，其中 XML 用 `ElementTree` 真解析（不是字符串包含）；转义、自链接、空日都测了。

### P7（本轮已完成）个性化反馈 + 突发即时推

**反馈闭环**
- ✅ `store` v5：`feedback` 表，同一身份同一天只保留最后一次态度（改主意覆盖，不累加）
- ✅ `prefs.py`：反馈 → 词级权重（`cat:` / `tag:` / `sub:` / `src:`）→ 排序微调（默认 ±8%）
- ✅ 只调排序、**不碰入选门槛**（门槛是公共标准，掺进偏好会让日报越来越窄）
- ✅ `serve.py`：`POST /api/feedback` 落库 + `GET /api/prefs` 看"它到底学到了什么"
- ✅ 卡片上的 👍/👎 按钮，点卡内按钮不会误触发跳转

**突发即时推**
- ✅ `push.py`：邮件 / Telegram / 通用 webhook，单通道失败不影响其他
- ✅ `breaking.py`：分数 ≥85 + 12 小时内 + 官方一手 + 永久去重 + 免打扰（23:00–08:00）
- ✅ `store` v6：`pushes` 表，同一条只推一次；**只在至少一个通道成功时才记账**

**过程中修掉的两个真 bug**
1. `prefs.terms_of` 只认 `Item` 对象，而 HTTP 请求里只有 dict —— **线上偏好会永远学不到东西**；
2. `only_primary` 只看信源层，把「HN 上的 Anthropic 官方博客」判成媒体 —— 那恰恰是最该推的一条。
   现在信源层与官方域名列表满足其一即算一手（有测试守子域名与仿冒域名的区别）。

**实测**：
```
反馈端点：POST up → 200 + terms；改成 down → 覆盖（1 行，kind=down）
          非法 kind → 400；未知条目 → 400；GET /api/prefs → 200
突发判定：真实 40 条里 1 条够格
          「Claude Fable 5.2 与 Mythos 5.2 发布」92 分 / 来自 HN 但落在 anthropic.com
```

**验收**：155 个测试全绿。

- ✅ `tools/eval_selection.py`：跑预筛 + 两次评分，终端出报告，逐条结果写 `data/eval/`
- ✅ `--enrich`：金标里没存正文时现抓

**口径（照 AIHOT 的三条）**：`either` 不进任何分母；失败不算进"准确率"但**算进"完整准确率"**；
准确率、覆盖率必须一起看，否则模型可以靠"少答"刷分。这条有专门用例
（答 1 条全对 → 准确率 100%、覆盖率 10%、完整准确率 10%）。

**本轮最重要的发现（把 P5 和 P8 连起来了）**：

```
同一条材料，补正文前后各打一次分：
  simonw「llm-anthropic 0.31 发布」   24 → 65
  simonw「用 Claude 定位蜂鸣声」      32 → 50
  simonw「隐藏低质 PR 描述」          39 → 71
```
**没有正文时，五轴评分器几乎只会给 20–40 分**，门槛 58/66/68 一条都过不了 ——
也就是说：不做正文提取，评分器等于没接上。带 `--enrich` 重跑同一批 8 条，
预测选中率从 0% 变成 12.5%，门槛扫描也终于有了区分度（40 分档选中 5 条、54 分档 2 条）。

**如实说明**：8 条样本是我为了验证工具链手工标的，**不是你的口味，也不足以校准门槛**。
真正的校准需要你标 100–200 条：
```
python tools/make_gold.py --n 120      # 生成 data/gold.jsonl
# 手工把每行 gold.decision 改成 select / reject / either
python tools/eval_selection.py --enrich
```
先看"判错"清单，再改 `config/prompts/attention-score.md`，**最后**才动 `config/scoring.yaml` 的门槛。

### P10（本轮已完成）全链路实跑与收口

在临时库 / 临时站点、推送打桩、不发邮件的条件下跑了一遍真正的 `run.main()`。
**前九轮积压的问题一次全暴露了**，这也是"分阶段单测"永远替代不了实跑的原因：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | `pipeline.run()` 返回 dict，而评分/结构/事件要 Item 对象 | 评分**静默跑了 0 条**、结构与事件 AttributeError，整轮仍然"成功"出报 | pipeline 返回对象，run.py 在三个阶段后统一 `to_dict()`；三个阶段收到 dict 一律抛 TypeError |
| 2 | 双次评分输入相同 → 回执键相同 | 第二次看到 `pending` 直接放弃：180 条里 **147 条判为失败** | `call_json(variant=)` 进键不进提示词；并发遇 pending 先等 20s 再放弃 |
| 3 | `to_dict()` 写在 translate 之前，而结构/事件排在 translate 之后 | 两个阶段又拿到 dict | 转换挪到事件之后 |
| 4 | 空数据库报"最近 3 天缺了 3 期" | **真的发出一封误报警邮件** | 只在库里出现过刊期之后才比较缺期 |

**修复前后（同一套真实数据，全链路）**：

| 阶段 | 修复前 | 修复后 |
|---|---|---|
| 评分 | 10 条打分 / 147 条失败 | **151 条打分 / 0 条失败** |
| 结构化 | AttributeError，0 条 | **118 条**（含 13 条综合稿） |
| 事件 | AttributeError，0 个 | **3 个**（合并 3 条） |
| 出口 | 5 个文件（只有 other 分类） | **9 个文件**（7 个 feed，分类齐了） |
| 全链路耗时 | 557s（多数阶段空转） | **967s**（真在干活） |

**修复后单条示例（6 条真实条目）**：
```
评分 6/6 成功、0 失败、3 条过门槛（82 / 77 / 81），分值区间 55–82 有区分度
结构 6/6：model_release 3 · opinion_analysis 2 · tool_or_prompt 1
理由示例：「主流厂商双模型正式发布、广泛可用，能力主张亮眼但均为二手 hype 转述，证据强度受限」
```

**遗留（下一轮要做）**：
1. **151 条里只有 8 条过门槛**（5%）—— 门槛偏严，但这正是 P8 金标要校准的东西，不靠拍脑袋调；
2. 全链路 967s ≈ 16 分钟，主要花在 471 次模型调用上，可以靠 `max_workers` 提速；
3. `items.json` 写在 export/board 之前，所以那两段 stats 不进产物（不影响文件本身）。

**教训（写进 `tests/test_contract.py`）**：阶段之间必须传同一种东西，传错了要炸，
不能悄悄降级成"跑完 0 条"。

### P12（本轮已完成）断点续跑

**为什么先做这个**：全链路约 16 分钟，中途任何一个阶段抛异常就整轮白跑 ——
包括已经跑完的 4 分钟抓取和 60 篇正文。这个风险比再加一个功能更值得处理。

- ✅ `collector/state.py`：抓取完成后把条目写成 `data/state-<day>.json`，读回时还原成 `Item`
- ✅ **只续"抓取 + 补正文"**（网络部分）。模型阶段本来就有回执保护，重跑很快也不花钱 ——
  少存一份中间状态，就少一类"状态与数据库不一致"的 bug
- ✅ 状态超过 12 小时不用（行情已经变了）；跑完即删，下次必是新的一轮；`--fresh` 强制重抓
- ✅ `prune()` 只留最近 3 天，`data/` 不会无限长
- ✅ `ensure_stats()`：续跑读回的是旧 stats，缺字段补齐再画 ——
  render / digest 不再因为缺 `registry` / `generated_at` 整页崩

**实测**：造一个 3 条目的状态 + 把 `pipeline` 标记为已完成 →
```
续跑: 复用 3 条已抓条目（跳过抓取与正文）
… 出站 / 出口 / 看板 / 时间线 / 日报 全部正常 …
状态文件还在吗: False          ← 跑完自动清
--- 第二次调用 ---
续跑: 没有状态文件，重新抓     ← 正确回退
```

**验收**：206 个测试全绿。

## 三、AIHOT 没有、但这里要有的（超越清单）

| # | 能力 | 为什么它没有 | 为什么这里值 |
|---|---|---|---|
| 1 | 可解释评分理由 | 公共站只展示分数 | 你要判断"模型真读懂了还是被标题骗"，理由比分数有用 |
| 2 | 权重由代码合成 | 让模型自己算总分 | 无算术错误、权重可扫、改口味不动提示词 |
| 3 | 个性化反馈闭环 | 公共站要匿名、无个人画像 | 单用户，读过的就是最强的信号 | ✅ P7 |
| 4 | 多通道 + 突发即时推 | 只有飞书，且按日出刊 | 新模型发布这类事，等一天就没意义了 | ✅ P7 |
| 5 | 中文舆论场双轴 | 示范源是海外 | 官方发布 vs 国内讨论，两条曲线常常背离，背离本身就是信号 | ✅ P9 |
| 6 | 本地模型全量打分 | 云 API 按量计费，必须省着用 | 本地网关边际成本≈电费，可以**每条都评**，而不是只评 Top N |
| 7 | 长期知识沉淀 | 召回窗口 14 天、归档即结束 | 你要的是"这条线和三个月前有什么不同" | ✅ P11 |
| 8 | 叙事对比 | 只有事件、没有"说法差异" | 官方稿 / 媒体报道 / 社区吐槽，三种口径并排看 | ✅ P11 |
| 9 | 日报可读性评测 | 只有精选/关系/综述三个评测 | 日报是每天真正被读的东西 |
| 10 | 单文件离线归档 | 有网页即可 | 断网、换机、给同事看，一个 HTML 就够 |

## 四、不采纳清单（避免把复杂度买回来）

| AIHOT 做法 | 不采纳的理由 |
|---|---|
| 三进程（api/worker/web）+ pg-boss | 单机每天一轮，多进程只增加故障面 |
| PostgreSQL + pgvector | 数据量在 10⁵ 级别，SQLite + 内存余弦足够 |
| `modules/` 模块化多租户 | 不做"卖给别人的行业模板" |
| 190+ 测试、75 个迁移 | 抄**规则**（一文件一语句、索引单独建、测试守行为），不抄数量 |
| MCP 服务 | 单机自用，`llms.txt` + JSON API 即可 |
| 后台增删改界面 | 配置就是 YAML，改文件比点界面快 |
