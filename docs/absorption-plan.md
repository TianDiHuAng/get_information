# AIHOT 能力吸收路线（全量对齐 + 反向超越）

> 目标：AIHOT 有的我都要有；AIHOT 没有的、对我有用的，我更要有。
> 约束：每一步都必须保证 `python run.py` 能跑完、产物不倒退。
> 对照对象：`docs/aihot-analysis.md`（它的实现细节与证据）。

---

## 总原则

1. **吸收的是机制，不是体量。** AIHOT 的 21k 行里有一大半是为"一套代码服务多个行业站 + 线上高并发"付的账，那部分不抄。抄的是它解决问题的**顺序**和**判据**。
2. **能配置的不写进代码。** 口径在 `config/scoring.yaml`，判断在 `config/prompts/`，代码只做机制。
3. **任何增强都必须可降级。** LLM 挂了、预算尽了、结果不明 —— 退回老路径，绝不阻断出刊。
4. **每一步都要能验证。** 没有验收标准的改造不做（见每期的"验收"）。

## 二、分期路线

### P1（本轮已完成）地基：存储 + 评分 + 回执

- ✅ `collector/identity.py`：身份与相似度
- ✅ `collector/store.py`：SQLite（条目/出现/已报/评分/回执/预算/阶段/信源）
- ✅ `collector/llm.py`：回执、预算、重试、备用模型、结构化解析
- ✅ `collector/rating.py`：预筛 → 五轴 ×2 → 门槛 → 降级
- ✅ `config/scoring.yaml` + `config/prompts/{prefilter,attention-score}.md`
- ✅ 接入 `pipeline.run()` / `run.py` / `digest.py`
- ✅ 28 个单测 + 离线冒烟

**验收**：`python -m pytest tests -q` 全绿；`run.py --skip-rate` 不依赖 LLM 也能出站和日报。

### P2（本轮已完成）事件聚簇 + 热度

- ✅ `collector/events.py`：IDF 加权 token 召回 → 只把够像的对送模型 → 四类关系判定 → 低置信度独立复核
- ✅ `config/events.yaml`：召回窗口/粗排门槛/预算闸/复核线/热度参数
- ✅ `config/prompts/{group-pair,group-review}.md`
- ✅ `event_pairs` 判定缓存：同一对永不重复付费（有测试守着）
- ✅ 热度 `Σ 0.5^(Δt/24h)` + 独立参与方 + `participant_groups`
- ✅ 代表稿选择 + 日报只出代表稿（`digest._pick`）+ `N 篇/N 家` 标注
- ✅ 单篇不建事件壳（215 条里 199 条），落库改为批量事务

**实测（真实 215 条，本地 glm-5.3-flash）**：
```
候选判定 24 对（一轮约 47s，4 并发）
→ 9 个多篇事件，合并 17 条
→ Claude Fable 5.2 一个事件合并 7 篇（HN / X×3 / Telegram / oneusefulthing）
→ 模型输出 confidence 0.85，回执 attempts=1，二次调用命中回执不花钱
```

**验收**：43 个测试全绿，其中 LG 那两条是活的回归用例。

### P3 结构化 + 内容指纹 + 防幻觉（下一步）

- `structure.md`：分类/标签/主体公司/一句话事实（谁做了什么对谁何时）。
- 内容指纹 `sha256(title|body|excerpt)`：转载改标题也能认出来。
- `grounded()`：标题摘要里的公司名、数字必须在原文出现，否则降级重写或丢弃。
- 精选写法 vs 廉价写法分档（`understand_floor`）。

**验收**：故意喂一条"原文没提的公司"，产出标题里不会出现它。

### P4 成刊规则化 + 运维

- 日报改规则编排（不调模型）：重要性 = 分数 + 5·log2(1+参与方) + 官方加成 − 跟进扣分。
- 空刊/缺期/补刊；周报月报从日报汇编。
- 心跳 + 告警（邮件/Telegram）：源连续失败、日报缺期、预算耗尽。
- 正文提取（评分不再只靠摘要）+ 日期解析补全（43 条无日期）。

**验收**：连续 7 天日报无缺期；源失败 30 分钟内能收到告警。

### P5 采集层工程化

- 统一 `Candidate` 契约 + 每类源配置白名单。
- 条件请求、间隔自适应、失败退避、试抓预览。

**验收**：新增一个源只需改 `config/*.yaml`，不改代码。

### P6 多出口

- `site/feed.xml`、`site/api/v1/latest.json`、`site/llms.txt`、按主题的 feed。
- 页面内搜索改成预生成索引（不再靠 254KB 内联）。

**验收**：能用 RSS 阅读器订阅；`llms.txt` 能被 Agent 直接读懂。

### P7 个性化与推送（超越项）

- 反馈闭环：点开/收藏/忽略 → `feedback` 表 → 标签级权重微调（bandit）。
- 多通道：邮件 + Telegram + 飞书；**突发即时推**（官方一手 + 分数 ≥ 高线 → 5 分钟内推）。
- 长期知识沉淀：月度时间线、公司/产品演进；Markdown/Obsidian 导出。

**验收**：连续一周，"我点开过的主题"在次日排序里权重可见上升。

### P8 评测体系（超越项）

- 金标：`data/gold.jsonl`，100–200 条人工标 select/reject/either。
- `tools/eval_selection.py`：准召 + 覆盖率 + 完整准确率 + 门槛扫描 40→90。
- 归组评测：4×4 混淆矩阵 + 各置信度门槛的 F1。
- **日报可读性评测**：同一批事件，两个版本日报并排比较（AIHOT 没有）。

**验收**：能回答"这一版比上一版好在哪，好多少"。

### P9 本地看板

单页 HTML：源健康、评分分布、成本、异常、已报/新增趋势。不做后台增删改（用 YAML 就够）。

## 三、AIHOT 没有、但这里要有的（超越清单）

| # | 能力 | 为什么它没有 | 为什么这里值 |
|---|---|---|---|
| 1 | 可解释评分理由 | 公共站只展示分数 | 你要判断"模型真读懂了还是被标题骗"，理由比分数有用 |
| 2 | 权重由代码合成 | 让模型自己算总分 | 无算术错误、权重可扫、改口味不动提示词 |
| 3 | 个性化反馈闭环 | 公共站要匿名、无个人画像 | 单用户，读过的就是最强的信号 |
| 4 | 多通道 + 突发即时推 | 只有飞书，且按日出刊 | 新模型发布这类事，等一天就没意义了 |
| 5 | 中文舆论场双轴 | 示范源是海外 | 官方发布 vs 国内讨论，两条曲线常常背离，背离本身就是信号 |
| 6 | 本地模型全量打分 | 云 API 按量计费，必须省着用 | 本地网关边际成本≈电费，可以**每条都评**，而不是只评 Top N |
| 7 | 长期知识沉淀 | 召回窗口 14 天、归档即结束 | 你要的是"这条线和三个月前有什么不同" |
| 8 | 叙事对比 | 只有事件、没有"说法差异" | 官方稿 / 媒体报道 / 社区吐槽，三种口径并排看 |
| 9 | 日报可读性评测 | 只有精选/关系/综述三个评测 | 日报是每天真正被读的东西 |
| 10 | 单文件离线归档 | 有网页即可 | 断网、换机、给同事看，一个 HTML 就够 |

## 四、不采纳清单（避免把复杂度买回来）

| AIHOT 做法 | 不采纳的理由 |
|---|---|
| 三进程（api/worker/web）+ pg-boss | 单机每天一轮，多进程只增加故障面 |
| PostgreSQL + pgvector | 数据量在 10⁵ 级别，SQLite + 内存余弦足够 |
| `modules/` 模块化多租户 | 不做"卖给别人的行业模板" |
| 190+ 测试、75 个迁移 | 抄**规则**（一文件一语句、索引单独建、测试守行为），不抄数量 |
| MCP 服务 | 单机自用，`llms.txt` + JSON API 即可 |
| 后台增删改界面 | 配置就是 YAML，改文件比点界面快 |
